# B站精准搜索

一个运行在 `search.bilibili.com` 的 Tampermonkey 用户脚本。它不替换 B站原生搜索，而是在页面上增加独立的“🎯 精准搜索”入口：从多个官方排序入口扩大候选池，先执行关键词相关性硬过滤，再让质量分只在相近相关性结果间辅助调序。

## 核心行为

```text
关键词
  → 综合 / 播放 / 最新 / 收藏（探索模式另加弹幕）多路召回
  → 仅保留真实视频卡，按 BV 号去重
  → 标题 / 标签 / 简介 / UP主 / 分区相关性评分
  → 模式对应的相关性与覆盖率硬门槛
  → 对通过门槛的视频计算质量百分位
  → 先按相关性分档，再在档内综合质量排序
```

- 默认匿名调用 B站公开搜索接口，不携带登录 Cookie，减少观看历史画像进入候选池的可能。
- 支持完整短语（`"澳网 决赛"`）和排除词（`-德约科维奇`）。
- 数字、年份和型号必须在标题、标签或简介中精确命中，质量分不能挽救错误型号。
- 每张卡显示“相关”“质量”、命中字段、缺失项与质量说明。
- 精准面板使用独立 Shadow DOM；原生搜索节点不会被删除或重建，关闭面板即可原样返回。
- 适配器集中在 `src/api-adapter.js`，端点、WBI 签名、响应清洗和风控处理与评分/UI 解耦。

## 三种模式

| 模式 | 候选池上限（去重前） | 相关性门槛 | 覆盖门槛 | 适合场景 |
|---|---:|---:|---:|---|
| 严格 | 4 路 × 2 页 × 50 | 70 | 75% | 明确标题、型号、比赛或作品名 |
| 标准 | 4 路 × 2 页 × 50 | 46 | 50% | 日常搜索，默认推荐 |
| 探索 | 5 路 × 3 页 × 50 | 25 | 25% | 冷门、长尾或允许近似拼写 |

实际候选通常远少于上限，因为同一视频会在多路结果中重复。并发固定为 2，并加入短暂间隔；同一查询和模式在当前页面缓存 5 分钟。

## 评分原则

相关性由词项覆盖、字段强度、标题覆盖、完整短语与词项邻近度组成。标题权重最高，标签次之，简介、UP 主和分区只能提供较弱证据。严格/标准模式只接受精确词项；探索模式才允许较高相似度的字面近似。

质量分使用播放、点赞、收藏、评论、弹幕、发布时间等接口已有数据。计数先取对数并做年龄调整，互动率使用贝叶斯平滑，再在候选组内转为百分位；缺失统计会向中性分收缩。查询包含明确往年（如 `2017`）时不使用发布时间时效项。

排序先按相关性分档，再在同档内按“相关性为主、质量为辅”的分数排序。因此，一个高播放但明显更不相关的视频不能跨档反超。

## 已知边界

- 脚本只能重排 B站接口返回的候选，无法发现完全未被官方搜索召回的视频。
- 相关性是本地字面匹配，不是大模型语义检索；别名、隐喻和完全不同写法可能需要探索模式或补充关键词。
- 搜索接口不会稳定返回投币、分享等全部统计；质量分会按可用字段重新归一化。
- B站可能调整接口或触发访问验证。脚本遇到 HTTP/JSON 风控状态会立即停止本轮请求，不会换端点绕过；稍后重试即可。

## 开发与验证

要求 Node.js 20 或更新版本：

```powershell
npm install
npm run verify
```

`npm run verify` 会做语法检查、运行测试、构建单文件 userscript，并再次检查构建产物语法。详细结果见 `TEST_REPORT.md`。

## 项目结构

```text
src/api-adapter.js   B站接口、WBI 签名、风控与规范化
src/text.js          查询解析和文本匹配基础
src/scoring.js       相关性硬门槛、质量评分和重排
src/ui.js            独立精准面板、解释卡片与分页
src/main.js          页面生命周期、SPA 同步、缓存和取消
dist/                可直接安装的单文件脚本
test/                自动化测试
```
